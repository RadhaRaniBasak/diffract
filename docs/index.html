Bob plans the split. Git builds and proves it.

Judgment comes from IBM Bob. Every number a reviewer sees comes from git, computed by the Diffract engine.

  1. Read the requirements

    Bob reads your design document or ticket, including Word files, and lists the requirements it describes.

  2. Map every change

    Explore subagents review the diff in parallel batches and label each hunk as mechanical or behavioural, with the requirement it serves.

  3. Approve the plan

    Bob proposes an order: shared groundwork first, then one slice per requirement. Nothing is built until you approve it.

  4. Build and test every slice

    The engine assembles each slice from your own hunks with git, checks it out in its own worktree, and runs your test command in all of them at once.

  5. Repair red slices

    When a slice fails, the engine reads the log, finds the hunks that define what is missing, and moves them. If the log gives no clue, it tests every candidate fix in parallel.

  6. Prove and publish

    It confirms the last slice equals your branch exactly, writes a stack map for reviewers, and opens stacked pull requests with status checks once you say yes.

Four rules the engine enforces.

The AI never edits code.
Slices are assembled from your own hunks with git plumbing.
Every hunk lands exactly once.
A plan that misses or repeats a hunk is rejected before anything is built.
Every slice passes on its own.
Each one is checked out separately and tested with your command.
Nothing ships without proof and your yes.
Publishing requires zero drift and an explicit approval.

Set up Diffract in IBM Bob.

About five minutes. You need Python 3.10 or newer, git 2.28 or newer, and IBM Bob. The GitHub CLI is optional and only used for publishing.

  1. Get the code and check the engine

    Draft: the repository link is not set yet, so the first command shows a placeholder.

    git clone <repository-url> diffract && cd diffract
python3 -m venv ~/.venvs/diffract
~/.venvs/diffract/bin/pip install -r mcp/requirements.txt
~/.venvs/diffract/bin/python mcp/smoke_test.py

    The last command should end with ALL CHECKS PASSED.

  2. Install the skill

    mkdir -p ~/.bob/skills && cp -r skills/diffract ~/.bob/skills/

  3. Register the MCP server

    In Bob, open the MCP settings, choose Edit Global MCP, and add this entry. Replace both paths with absolute paths on your machine.

    {
  "mcpServers": {
    "diffract": {
      "command": "/Users/you/.venvs/diffract/bin/python",
      "args": ["/Users/you/diffract/mcp/diffract_mcp.py"],
      "alwaysAllow": ["start_session", "set_requirements", "show_units",
        "annotate_units", "set_plan", "move_units", "merge_slices", "verify",
        "probe", "locate", "drift_check", "status", "report"],
      "disabled": false
    }
  }
}

    Publishing and cleanup are left out of the list on purpose, so Bob always asks before it pushes or deletes anything.

  4. Split a pull request

    Open the repository in Bob, switch to Agent mode, and send:

    /diffract Split feature/my-branch against main. Verify with "npm test".

    Bob shows you the plan before building anything, and asks again before publishing.

To reproduce the recorded demo first, run this from the repository. It builds the 13-PR branch and a matching test environment.

bash demo/setup_click_demo.sh ~/click-demo

Or let it run on every pull request.

The Diffract GitHub Action plans a split for each pull request over the budget, tests every slice with your command, repairs what fails, and comments the verified plan. There's no server to run.

Beta

Add this file to your repository as .github/workflows/diffract.yml:

name: Diffract
on:
  pull_request:
    types: [opened, synchronize, reopened]
permissions:
  contents: read
  pull-requests: write
jobs:
  split:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: YOUR-GITHUB-USER/diffract@main
        with:
          setup: "npm ci"
          verify: "npm test"

Its plans follow Diffract's rules rather than your design document, and every slice is still built from your own hunks and tested. For plans that follow your requirements, run Diffract in IBM Bob.

On pallets/click #3030 with click's own tests, the engine behind the Action made 5 automatic repairs and ended with every slice green and zero drift, in about a minute on one CPU.

Questions reviewers ask.

Does Diffract change my code?

No. Each slice is assembled from your own hunks with git plumbing, and before anything is published the engine checks that the last slice's tree equals your branch's tree.

What happens after the first pull request merges?

Merge the stack from the bottom using merge commits. Each remaining pull request then shows only its own changes.

Which languages does it work with?

Any git repository with a command that builds and tests it. We have tested it on Python projects, including pallets/click. Other stacks are untested so far.

Do I need GitHub?

Only for publishing, and GitLab works too. Splitting, testing and the stack map work on any local git repository. Publishing opens stacked pull requests on GitHub with the gh command, or stacked merge requests on GitLab with glab.

Does it run on Windows?

Diffract is tested on Linux and on an Intel Mac. Windows support is built in, including a PowerShell version of the demo setup, but it hasn't been tested on a Windows machine yet. The setup commands above are for macOS and Linux shells.

Can it check what a pull request claims?

Yes. Include the pull request description, or an AI agent's report, in your request to Bob. Bob lists its factual claims, such as "no API changes" or "tests unchanged", and Diffract's facts tool checks each one against the actual changes, including test edits that remove assertions. Claims that don't hold go into the report.

Who this covers

This policy covers the Diffract website and the Diffract software, a hackathon project. For questions or requests, open an issue in the project's repository.

This website

This website is a single static page. It sets no cookies, runs no analytics, and loads no fonts, scripts or images from other servers. The images and the sample report are embedded in the page itself.

When you use Preview a split with a pull request or merge request link, your browser requests that change's public data directly from GitHub or GitLab. Their privacy policies apply to those requests. Diffs you paste and run files you open are processed in your browser and are never uploaded.

The service that hosts the page may record technical information, such as your IP address, when you load it.

The Diffract software

Diffract runs on your own computer. It reads the git repository you point it at and writes working files in two places: a .diffract folder inside that repository, and git worktrees under ~/.cache/diffract or the folder set in DIFFRACT_WORKTREE_ROOT.

Diffract does not send your code or any usage information to the Diffract team.

Services you connect

  • When you run Diffract inside IBM Bob, Bob and the AI models it uses process your prompts and code under IBM's terms and privacy policy.
  • When you publish, Diffract uses your GitHub CLI and GitHub account to push branches, open pull requests and post commit statuses. GitHub's terms and privacy policy apply.
